Exam-thinking loop

When you see a question, don't ask “what formula do I remember?” Ask what state the data structure must maintain.

1. Identify the invariant

Binary search: the key, if present, stays inside [lo, hi]. Circular queue: front/rear describe the live region. Stack: top is the only legal access point.

2. Identify the state-changing line

For every algorithm, find the line that actually changes the state: hi=mid-1, p->link=temp, rear=(rear+1)%N, push(), etc.

3. Simulate one iteration

Write the state before → execute one branch → write the state after. Most tracing mistakes happen when people mentally skip this transition.

4. Check the invariant again

If it still holds, continue. If it breaks, your line order, boundary condition, or operator-operand order is probably wrong.
