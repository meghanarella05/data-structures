Study rule: every time you meet a topic, first identify the business problem. Only then learn the procedure.

DAY 1 — 🔎 “Find this customer.”

You have millions of sorted customer IDs. Someone gives you one ID.

10M IDs
→
Need 1 ID
→
Throw away
half each time

That's Binary Search.

low ───────────────────────── high
                 │
                mid
                 ↓
        compare key with a[mid]

key smaller → discard RIGHT half
key bigger  → discard LEFT half

MENTAL MODEL

“Where could the answer still possibly be?”

Exam trace = low | high | mid. The table is just the search space shrinking.

DAY 2 — 🔀 “Our data is a mess. Sort it.”

🫧 Bubble Sort

Fix local disorder by comparing neighbours.

81 23 47 5
↓  compare neighbours
23 47 5 81
             ↑
        largest locked
Think: “Big things bubble to the end.”
🎯 Selection Sort

Find the smallest remaining item and lock it into place.

 ? ? ? ? | sorted
 ↓
minimum → first free slot
Think: “Pick the next winner.”
🃏 Insertion Sort

Keep a sorted prefix; insert the next item into it.

5 19 23 47 | 14
             ↓
5 14 19 23 47
Think: “My left hand is already sorted.”

DAY 6 — 🔗 “Our records need to grow dynamically.”

Singly Linked List

A
→
B
→
C
→
NULL

Each node knows where the next node is.

Business problem: insert/delete without shifting an entire array.

😈 “Insert Meghu between B and C.”

BEFORE:
A → B → C → D

SAFE:
M → C       (save the old link)
B → M       (then redirect B)

AFTER:
A → B → M → C → D
Core invariant: DON'T destroy the route to the rest of the list before you've saved it.

This is why pointer-ordering questions exist. They test whether you can preserve the structure, not whether you can admire C syntax.

↔️ Doubly Linked List

A
↔
B
↔
C

Now each node knows previous + next. Insertion/deletion means fixing both directions.

DAY 8 — 🎟️ “Customers are waiting.”

Queue = First In → First Out

A
→
B
→
C
→

A gets served first. Enqueue at rear. Dequeue at front.

Think: “It's literally a waiting line.”

DAY 9 — 🔄 “The queue wastes space.”

Circular Queue

Linear queue:
[ _ ][ _ ][ C ][ D ][ E ]
  ↑ free space       ↑ rear

Problem:
rear reached the physical end,
but the front has empty cells.

Circular solution:
[ F ][ G ][ C ][ D ][ E ]
  ↑
wrap around!

FULL condition:
(rear + 1) % N == front

Think: “The array is a ring, so rear can wrap around.”

DAY 10 — 🚪 “Sometimes I need both ends.”

Deque

INSERT
↔
A B C
↔
DELETE

Insertion and deletion can happen at both ends.

Think: “Queue, but both doors work.”

DAY 11 — 🚨 “Arrival order isn't enough.”

Priority Queue

Patient A → priority 4
Patient B → priority 1
Patient C → priority 3

SERVE:
B → C → A

Why?
Priority determines service order.
Equal priority → FIFO.

Think: “Who should be served next depends on importance, not arrival.”

Engineering trade-off: an ordered-list representation makes insertion O(n) and deletion O(1); an unordered list reverses that trade-off.

DAY 12 — 🧮 “Our software receives expressions.”

Infix → Postfix

A + B * C
→
STACK
→
ABC*+
SCAN LEFT → RIGHT

operand  → output
(        → stack
)        → pop until (
operator → use precedence + stack
end      → pop remaining operators

^  >  * /  >  + -

Think: “Which operators are waiting for their turn?”

Postfix Evaluation

2 3 + 4 *

2 → push
3 → push
+ → pop 3, pop 2 → 5 → push
4 → push
* → pop 4, pop 5 → 20

ANSWER = 20

Critical: in postfix, the first pop is the RIGHT operand.

🧷 Parenthesis Matching

{ [ ( ) ] }

opening bracket → PUSH
closing bracket → check most recent opening bracket
end → stack must be EMPTY

Same stack. Different business problem. That's the point.

🧠 Your 4-question cheat code

1WHAT DO I HAVE?

Array? chain? stack? queue? matrix? expression?

2WHAT DO I NEED?

Find? sort? insert? delete? evaluate? serve?

3WHAT MUST NOT BREAK?

Search interval? links? LIFO/FIFO? front/rear? operator order?

4WHAT DOES THE STATE BECOME?

Trace it one operation at a time. Don't jump.

⚡ Then practice — don't over-study

Read the heuristic for one topic.
Say the business problem in one sentence.
Do one drill carefully.
Do a fresh drill WITHOUT the heuristic.
If you recognize + execute it cleanly → MOVE ON.
If you blank or make structural mistakes → one more rep.
THE ACTUAL GOAL:

You don't want to remember “Module 3 = postfix question.”

You want to see an expression and immediately think:

“Ah. This is an ordering/state problem. The stack is the temporary memory.”

That's when the syllabus stops being a list and becomes a machine.
